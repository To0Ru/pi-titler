## 已采纳

* **D1 显式标题模型**：未指定模型不命名，不自动探测便宜模型；会话模型回退默认关闭。理由：费用可控、行为可预期。替代了“探测便宜模型 + 自动回退 + 截断兜底”。
* **D2 失败不写替代标题**：保留 Pi 默认名称，不截断用户消息充当标题。
* **D3 手动重新生成直接替换**：`/titler` 选择即授权，无需确认；候选确认方案未采用。
* **D4 整套会话快照**：首次修改即复制完整配置，不按字段继承（用户明确否决逐项继承）。
* **D5 历史会话补命名默认关闭**；打开旧会话本身不发请求。
* **D6 菜单**：首页去掉重复的模型入口；统一 Pi 列表风格、Esc 逐级返回、两列对齐、固定说明区（来自用户截图验收）。
* **D7 自动命名开关** `autoNaming`，默认开启，只管自动入口。
* **D9 文档分工**：`AGENTS.md` 只放硬性约束与协作约定；现状写 `design.md`，讨论与提议写本文件。理由：`AGENTS.md` 每次会话都加载，长篇历史浪费上下文，且会让 Agent 把旧方案当教条。
* **D10 本地纯文本结构化摘要**：纯文本发送，废弃大段 JSON；工具足迹同类合并（修改/命令/搜索/读取单列说明）；用户消息代码块折叠为 `[代码 N 行]`；排除系统词/思考块/branch_summary；CJK 字符估算 Token；自动（~1200 token）与手动（~2000 token 带时间线与投入量）分立设计。
* **D11 自动命名触发简化**：移除工具计数触发；改为每条用户消息并行发起（意图明确即刻命名，含糊允许 `NO_TITLE`）+ `agent_settled` 带助手回复和足迹重试 + 第 3 条用户消息强制命名。

## 替代

* **D8 触发规则（替代 → D11）**：第 3 次工具调用 / `agent_settled` / 第 3 条用户消息。演进：仅首轮结束 → 加工具信号 → 加三条消息上限。被替代原因：第 3 次工具调用常处于侦察阶段，易产生泛化标题；与 settled 职责重叠。
